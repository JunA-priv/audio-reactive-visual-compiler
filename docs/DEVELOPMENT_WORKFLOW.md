# 開発フロー

DECIDED：要件→責務・契約→実装→単体→統合→E2E→セキュリティ/品質→ドキュメント照合→人のレビュー→受け入れ。

1. CURRENT_STATEと対象仕様を読み、現在の差分を確認する。
2. CURRENT_TASKに今回の対象・完了条件を記載する。
3. 作業ブランチで実装し、変更に適したテストを実行する。
4. 依存変更時は公式情報、lock、間接依存を確認する。
5. 設計書とCURRENT_STATE、reportsを更新する。
6. PRへ結果と未検証事項を明記し、人の受け入れを待つ。

DECIDED：通常CIとデプロイを分離し、通常CIへ本番Secretを渡さない。CI迂回の自動公開経路を作らない。報告はcompleted/partial/blockedを使う。
