# Step 7k-28 — Audio Analyze失敗の調査

**状態: 部分完了。** ユーザーのWindows Chrome/Goプロセスでは報告された失敗を再現できていないため、発端となった原因は未確定です。指定された43.14〜103.14秒の切り出し形式をローカルで検証し、60秒のGo→Python解析でHTTP 200を確認しました。4種類すべてのGate Modeリクエスト経路が成功し、誤解を招くHTTP 422の文言も修正しました。

## 調査結果

### 表示エラーの発生元

`frontend/src/audio-analysis.ts`はHTTP 422を報告された日本語エラーに対応付けています。現行のGo handlerでは、(a) multipart音声パートが不正・欠落・重複している、または未知のmultipartフィールドがある場合（`receive_audio`）、もしくは(b) WAVがffprobeによる形式、コーデック、サンプルレート、チャンネル数、長さの検証に失敗した場合（`probe`）に、Python実行前に422を返します。現行handlerは音量を検査しません。Pythonプロセスの失敗は502、リクエストサイズ超過は413、解析タイムアウトは504に対応します。そのため表示されていた「音量」の案内は不正確で、どちらの422経路かも特定できていませんでした。

### FrontendリクエストとGate Mode

- CropperはWeb Audioでソースをデコードし、44.1kHzステレオの`OfflineAudioContext`で選択フレームを正確に描画して、44byteのRIFF/WAVEヘッダーにPCM16サンプルを続けて書き出します。
- 43.14〜103.14秒の選択範囲は、44.1kHzで正確に2,646,000フレーム（60,000ms）で、標準WAVサイズは10,584,044 bytesです。
- リクエストはブラウザーが生成するmultipart `FormData`で、`audio`ファイル1つと`kickGateMode`テキストフィールド1つを含みます。multipart境界はブラウザーが設定します。FrontendとGoのテストでOff、Soft、Middle、Hardを確認し、省略時は引き続きHardです。
- 現行Goパーサーは`kickGateMode`を明示的に受け付けます。Step 7k-25以前に起動したGoプロセスは古い厳格なmultipart処理のまま動作し、この新フィールドを422で拒否する可能性があります。これは妥当な原因候補ですが、Windowsプロセスのバージョンとリクエスト段階のログをこの環境から確認できなかったため確定ではありません。

### 切り出し音声の検証

リポジトリの`audio-reactive-silent-demo4.mp3`はコンテナ長189.984秒です。独立したFFmpeg処理で43.14秒から60秒を切り出し、ffprobeにより`pcm_s16le`、44,100Hz、2チャンネル、60.000秒のWAVと確認しました。デコードしたサンプルは無音ではありません（peak 18,389 / 32,767、RMS 4,168.64 / 32,767）。元のMP3は変更していません。これは利用可能なソースに対する時間範囲と想定PCM形式を確認したもので、ユーザーの失敗リクエストからブラウザー生成バイト列を取得したものではありません。
